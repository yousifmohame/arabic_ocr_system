# Arabic Doc AI — Local OCR Engine (v0.3.0)

نسخة أولية لمحرك OCR عربي محلي يعمل على CPU. تعالج الصور وملفات PDF صفحة واحدة في كل مرة، وتخرج النصوص مع درجات الثقة ومربعات مواقعها.

> هذه نسخة MVP لقراءة النصوص فقط. لم ننفذ بعد استخراج الحقول المتخصصة أو مراجعة النتائج عبر Tesseract أو API أو واجهة رسومية.

## 1) المتطلبات

- Python 3.10 أو 3.11 مفضلان.
- ذاكرة 8GB كهدف تشغيل أولي.
- CPU فقط؛ لا يتم طلب GPU.
- تثبيت PaddlePaddle CPU المناسب لنظام التشغيل والمعمارية.

تحقق أولًا من البيئة:

```bash
python3 scripts/check_environment.py
python3 --version
python3 -c "import platform; print(platform.system(), platform.machine())"
```

## 2) إعداد بيئة افتراضية

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip wheel setuptools
```

### تثبيت PaddlePaddle CPU

ارجع إلى صفحة التثبيت الرسمية واختر العجلة المطابقة لنظامك ومعالجك:

https://www.paddlepaddle.org.cn/en/install

في توزيعات Linux/Windows التي تدعم عجلة CPU، توثق PaddlePaddle حاليًا أمرًا من هذا الشكل (تحقق من الإصدار المدعوم عند التثبيت):

```bash
python -m pip install paddlepaddle==3.3.1 -i https://www.paddlepaddle.org.cn/packages/stable/cpu/
```

ملاحظة مهمة لمستخدمي Mac: دعم PaddlePaddle يختلف باختلاف إصدار macOS ومعمارية Intel/Apple Silicon. لا تستخدم أمر Linux/Windows أعلاه تلقائيًا على Mac. نفّذ تقرير البيئة أولًا، ثم استخدم صفحة التثبيت الرسمية المطابقة لجهازك. إذا لم تتوفر عجلة متوافقة، سنبدّل محرك التنفيذ إلى ONNX Runtime بعد تحويل النماذج أو نختار backend مدعومًا، دون تغيير بقية المشروع.

## 4) أول تشغيل للنماذج

نستخدم كاشف النصوص `PP-OCRv5_mobile_det` ونموذج التعرف العربي `arabic_PP-OCRv5_mobile_rec`.

**مهم:** يتطلب هذا الإصدار PaddleOCR 3.3.x مع PaddleX 3.3.x. ينزّل المشروع ملفات النموذجين صراحةً إلى مجلد `models/`، ثم يمرر مساريهما المحليين مع اسمي النموذجين المطابقين لملفات `inference.yml`.

أول تشغيل يحتاج اتصالًا بالإنترنت لتنزيل الملفات من مستودعات PaddlePaddle على Hugging Face:

```bash
python scripts/prepare_models.py
```

بعد اكتمال التجهيز، شغّل صورة اختبار فعلية. أصبح مسارا النموذجين داخل المشروع، ولا يحتاج الاستدلال إلى تنزيلهما من جديد. اقرأ `models/README.md` قبل نقل المشروع أو تشغيله على جهاز غير متصل.

## 5) تشغيل OCR

صورة:

```bash
arabic-doc-ocr data/input/document.jpg
```

PDF:

```bash
arabic-doc-ocr data/input/document.pdf --dpi 220 --max-side 2800 --threads 2
```

تحديد ملف الإخراج:

```bash
arabic-doc-ocr data/input/document.pdf -o data/output/result.json
```

ينتج ملف JSON وملف TXT بجوار ملف JSON. تعمل المعالجة المسبقة افتراضيًا، ويمكن تعطيلها للمقارنة باستخدام `--no-preprocess`.

## 7) تاريخ المعالجة المسبقة في v0.2.0

كان v0.2.0 يطبق سلسلة معالجة ثابتة. هذا السلوك استُبدل في v0.3.0 بالاختيار التكيفي الموضح في القسم 11:

- اكتشاف محافظ لحدود المستند في الصور الفوتوغرافية وتصحيح المنظور عند توفر شكل رباعي موثوق.
- تحسين محلي خفيف للتباين (CLAHE) وحدّة معتدلة، دون تحويل الصورة إلى أبيض وأسود.
- تكبير الصور الصغيرة حتى 2x ضمن حد أقصى لحجم الصفحة.
- إرجاع إحداثيات مربعات OCR إلى إحداثيات الصورة/الصفحة المصدر، مع الاحتفاظ بإحداثيات الصورة المعالجة في `bbox_processed`.
- لا يُجرى تصحيح منظور لصفحات PDF لأنها تُعامل على أنها صفحات مسطحة أصلًا.

هذه الإعدادات تشرح آلية الإصدار التاريخي؛ في v0.3.0 أصبح الوضع الافتراضي هو `adaptive`، ويمكن تشغيل الأصل فقط باستخدام `--preprocess-mode baseline` أو `--no-preprocess`.

## 8) حدود النسخة الحالية

- اكتشاف حدود المستند مبني على contours وقواعد هندسية؛ إذا لم تكن الثقة كافية، يحتفظ النظام بالصورة الأصلية بدل قص خاطئ.
- لا يزال ترتيب القراءة تقريبيًا: من أعلى لأسفل، ومن اليمين لليسار داخل الصف الواحد. الأعمدة والجداول تحتاج محلل تخطيط متخصصًا.
- تحسين الصورة لا يضمن تحسن OCR لكل مستند؛ يجب مقارنة CER وWER على مجموعة اختبار ثابتة.
- لا نعتبر درجة OCR احتمالًا معايرًا لصحة النص.
- لا يوجد حاليًا OCR ثانٍ أو استخراج حقول أو تخزين قاعدة بيانات.
- لا ترسل مستندات شخصية أو حساسة للاختبار قبل مراجعة سياسة الاحتفاظ بالملفات على جهازك.


## 9) الدرس المستفاد من اختبار v0.2.1

أظهرت مقارنة صورة بطاقة فعلية أن المعالجة الكاملة قد تضر بعض الحقول: قد يدمج تصحيح المنظور أرقامًا متجاورة أو تتراجع قراءة بعض الكلمات العربية. لهذا السبب لا يعتمد v0.3.0 معالجة ثابتة؛ بل يشغّل الأصل أولًا، ثم يقارن المرشحين الذين تدعمهم مؤشرات جودة الصورة.

لا تستخدم متوسط ثقة OCR بديلًا عن CER/WER، ولا تعتمد نتيجة المحرك في الإنتاج دون Ground Truth على مجموعة اختبار ممثلة.

## 11) Intelligent Preprocessing (v0.3.0)

يبدأ v0.3 دائمًا بقراءة الصورة الأصلية، ثم يحلل خصائصها ويقترح عددًا محدودًا من التحويلات المستقلة. لا يفترض أن الصورة المحسّنة أفضل؛ يحتفظ بالنسخة الأصلية ما لم يتفوق أحد المرشحين على نتيجة الأصل بهامش واضح وفق تقييم heuristic.

### مؤشرات جودة الصورة

يحسب المحرك محليًا وبعينة مصغّرة:

- متوسط السطوع والتباين والانحراف المعياري.
- المدى الديناميكي بين المئينين 5 و95.
- مؤشر الحدة عبر تباين Laplacian.
- تفاوت الإضاءة منخفض التردد.
- كثافة الحواف.
- زاوية الميل التقريبية ودعم خطوط Hough.
- خصائص منطقة المستند فقط عندما يكتشف كاشف الحدود رباعيًّا موثوقًا؛ وبذلك لا تهيمن الخلفية السوداء على قياسات البطاقة.

هذه قياسات وصفية للصورة، وليست قياسًا لدقة OCR.

### المرشحون في v0.3

1. `perspective`: تصحيح المنظور عند اكتشاف حدود وثيقة موثوقة وتشوه هندسي كافٍ.
2. `deskew`: تصحيح الميل باستخدام خطوط Hough طويلة مع حد أدنى للزاوية والدعم.
3. `enhancement`: تحسين CLAHE وحدّة خفيفة عند ظهور مؤشرات مناسبة.
4. `upscale`: تكبير الصور الصغيرة ضمن حدود الذاكرة.

تُعالج المرشحات بالتتابع، ولا تعمل بالتوازي. الأصل دائمًا مرشح أساسي. العدد الافتراضي للمرشحين الإضافيين هو ثلاثة، ويمكن تعديله.

### اختيار النتيجة

يقيّم المحرك كل نتيجة بمزيج من متوسط/وسيط ثقة OCR، وسلامة النص، ونسبة الأسطر المفيدة، وتغطية صناديق المواقع، وتداخلها، والتشابه مع نتيجة الأصل واستقرار عدد الأسطر. توجد عقوبة صغيرة على التحويلات لتفضيل الأصل عند التعادل.

**مهم:** درجة الاختيار heuristic وليست احتمال صحة أو بديلًا عن Ground Truth. قد يختار النظام نتيجة تبدو أفضل وفق المؤشرات لكنها ليست أدق حرفيًا. لذلك لا تعتمد النتيجة في الإنتاج قبل قياس CER/WER على مجموعة وثائق كتبت نصوصها المرجعية يدويًا.

### تشغيل الوضع التكيفي

```bash
export DISABLE_MODEL_SOURCE_CHECK=True
export OMP_NUM_THREADS=1
export OPENBLAS_NUM_THREADS=1

python -m arabic_doc_ai.cli data/input/test2.jpg \
  --threads 1 \
  --preprocess-mode adaptive \
  --max-preprocessing-candidates 3 \
  -o data/output/test2-v03.json
```

### قياس كل مرشح باستخدام نص مرجعي

أنشئ ملف UTF-8 يحتوي النص الصحيح للصفحة كما يظهر في الصورة، ثم شغّل:

```bash
python -m arabic_doc_ai.cli data/input/test2.jpg \
  --threads 1 \
  --ground-truth data/input/test2-ground-truth.txt \
  -o data/output/test2-v03-evaluated.json
```

سيظهر لكل مرشح `cer` و`wer` داخل `pages[].preprocessing.candidates[].metrics`، إلى جانب مؤشرات الجودة ودرجة الاختيار. لا تُستخدم قيم Ground Truth لاختيار النتيجة تلقائيًا؛ إنها للقياس فقط حتى لا نخفي تحيز الاختبار.

في مستند PDF متعدد الصفحات، افصل النص المرجعي لكل صفحة بمحرف form-feed (`\f`) وبنفس ترتيب الصفحات.

لإنشاء تقرير مقارنة بصيغة Markdown وJSON وقياس ذروة الذاكرة والزمن:

```bash
python scripts/compare_preprocessing.py data/input/test2.jpg \
  --threads 1 \
  --ground-truth data/input/test2-ground-truth.txt \
  --output-dir data/output/test2-v03-report
```

### التحكم في المسار

- `--preprocess-mode baseline`: قراءة الأصل فقط.
- `--preprocess-mode adaptive`: قراءة الأصل ثم المرشحين الذين تقترحهم مؤشرات الصورة.
- `--max-preprocessing-candidates 0..5`: حد إضافي لعدد عمليات OCR لكل صفحة.
- `--selection-margin 0.015`: الحد الأدنى المطلوب لتفوق المرشح على الأصل.
- `--no-perspective-correction`, `--no-deskew`, `--no-enhance`, `--no-upscale`: استبعاد عملية بعينها من التوليد التكيفي.

المعالجة التكيفية تزيد زمن الصفحة لأنها قد تنفذ أكثر من تمريرة OCR، لكنها تظل تسلسلية وتستخدم النموذج نفسه المحمّل مرة واحدة. لم نثبت بعد حد ذاكرة عمليًا على جهاز 8GB؛ يجب قياس Peak RSS على Mac المستهدف.
